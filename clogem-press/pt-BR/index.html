O que é o clogem-press

O clogem-press gera um site estático a partir de uma pasta de arquivos Markdown: uma base de conhecimento, um blog, uma documentação, ou os três em um só site. Ele segue as convenções de conteúdo do vuepress-theme-vdoing: pastas numeradas viram a barra lateral, o front matter é escrito automaticamente e cada artigo ganha um endereço permanente curto.

Ele roda no babashka (em inglês), sem nenhuma biblioteca para instalar: Markdown, templates, YAML, HTTP e feeds já vêm embutidos no babashka.

Um site pode ter até cinco idiomas: inglês, chinês simplificado e chinês tradicional, malaio e tâmil. As versões de um artigo compartilham um único endereço, para que o leitor possa alternar entre elas.

Primeiros passos

Você precisa do babashka (em inglês) 1.13.219 ou mais recente, e do git. O clogem-press roda a partir da pasta do seu site, usando uma cópia do gerador ao lado dela:

git clone https://github.com/EchoJustus/clogem-press
cd my-site
bb --config ../clogem-press/bb.edn dev      # build, serve on localhost:1888, rebuild on change
bb --config ../clogem-press/bb.edn build    # write the site to dist/
bb --config ../clogem-press/bb.edn doctor   # report content problems without building
  • O README (em inglês): todas as tarefas e opções, as convenções em uma tela só e as configurações do tema.
  • O site de demonstração (em inglês): um site completo para copiar, que os testes geram a cada mudança.
  • config.example.edn: cada configuração com o seu valor padrão.
  • DESIGN.md (em inglês): o design e os motivos por trás dele.

Privacidade

Esta página

Esta página não define cookies, não executa nenhum script e não carrega nada de outros sites: os seus estilos e o seu ícone estão dentro deste único arquivo. O GitHub Pages, que a serve, mantém os seus próprios registros das solicitações que recebe, conforme descrito na declaração de privacidade do GitHub (em inglês). Os links para o GitHub levam você ao GitHub, sob os termos dele.

O gerador

O clogem-press roda no seu próprio computador. Ele não tem conta, telemetria nem verificação de atualizações, e não envia nada sobre você ou o seu conteúdo para lugar nenhum.

Ele só acessa a internet para baixar uma ferramenta de que precisa, por padrão das versões publicadas da própria ferramenta no GitHub:

  • Chroma, para destaque de código, na primeira geração de um site que tenha código, a menos que o destaque esteja desativado;
  • Pagefind, para busca, na primeira geração de um site que ative a busca;
  • o pod fswatcher, que observa os seus arquivos, na primeira vez que você executa bb dev;
  • ou qualquer um deles quando você executa bb fetch-tool.

Cada download é verificado com um hash SHA-256 fixado no clogem-press e guardado em um cache fora do seu site (por padrão, ~/.cache/clogem-press/tools), então acontece só uma vez. A configuração de um site pode, em vez disso, indicar outra origem e outro hash para uma ferramenta. Uma cópia já instalada, indicada na configuração do site ou em CLOGEM_CHROMA, CLOGEM_PAGEFIND ou CLOGEM_FSWATCHER, nunca é baixada.

Os sites que você gera

Um site gerado com o clogem-press é uma pasta de arquivos que você publica onde quiser. Por padrão, ele não faz nenhuma solicitação a outro site. Ele só faz isso quando o dono ativa os comentários do giscus ou uma ferramenta de análise (Google Analytics 4, Plausible ou Umami), ou informa um logotipo ou uma imagem como um endereço em outro site. As tags de verificação de consoles de busca, se o dono as adicionar, são linhas na página que não carregam nada. Por conta própria, um site guarda três coisas no navegador do leitor (o modo de cor escolhido, o idioma escolhido e quais avisos de idioma “também disponível em…” o leitor fechou) e não envia nada disso para lugar nenhum; os comentários do giscus e a análise, quando o dono os ativa, guardam os próprios dados, sob os próprios termos.
