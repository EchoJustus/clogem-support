What clogem-press is

clogem-press builds a static website from a folder of Markdown files: a knowledge base, a blog, documentation, or all three in one site. It follows the content conventions of vuepress-theme-vdoing: numbered folders become the sidebar, front matter is written for you, and every article gets a short permanent address.

It runs on babashka, with no library to install: Markdown, templates, YAML, HTTP and feeds all come built into babashka.

One site can hold up to five languages: English, Simplified and Traditional Chinese, Malay and Tamil. An article's versions share one address, so a reader can switch between them.

What it does today

The latest release is 0.2.0. Work on the next phase is in progress on the main branch and is not released yet. The changelog lists every change as it lands.

Released · 0.2.0

Content and structure

A sidebar from numbered folders, front matter written for you with stable permanent links, category, tag and archive pages, a paginated blog home with pinned posts, breadcrumbs, previous and next links, catalogue pages and Markdown containers.

Released · 0.2.0

Languages and discovery

Five languages with one address per article, canonical and hreflang links, an Atom feed per language, a sitemap, Pagefind search with an index per language, and optional giscus comments with one thread per article.

In progress · unreleased

The theme, on the main branch

Landed so far: light, dark and reading colour modes, code highlighting, card and line page styles, a navbar with a mobile drawer, edit links and last-updated dates, a 404 page, the blog's profile card and home banner, optional analytics and search-console tags, and a quicker bb dev: one rebuild per burst of saves, build errors shown in the browser, the theme reloaded as it changes, and a site's base path served as it will be published. Still to come in this phase: custom HTML slots and search across languages, then the next release.

Getting started

You need babashka 1.13.219 or newer, and git. clogem-press runs from your site's folder against a copy of the generator beside it:

git clone https://github.com/EchoJustus/clogem-press
cd my-site
bb --config ../clogem-press/bb.edn dev      # build, serve on localhost:1888, rebuild on change
bb --config ../clogem-press/bb.edn build    # write the site to dist/
bb --config ../clogem-press/bb.edn doctor   # report content problems without building

The generator

clogem-press runs on your own computer. It has no account, no telemetry and no update check, and it sends nothing about you or your content anywhere.

It goes online only to download a tool it needs, by default from that tool's own releases on GitHub:

  • Chroma, for code highlighting, on the first build of a site that has code in it, unless highlighting is off;
  • Pagefind, for search, on the first build of a site that turns search on;
  • the fswatcher pod, which watches your files, the first time you run bb dev;
  • or any of them when you run bb fetch-tool.

Each download is checked against a SHA-256 hash pinned in clogem-press and kept in a cache outside your site (by default ~/.cache/clogem-press/tools), so it happens once. A site's config can instead name its own source and hash for a tool. A copy already installed, named in the site's config or in CLOGEM_CHROMA, CLOGEM_PAGEFIND or CLOGEM_FSWATCHER, is never downloaded.

The sites you build

A site built with clogem-press is a folder of files that you publish where you choose. Out of the box it makes no request to another site. It does so only when its owner turns on giscus comments or analytics (Google Analytics 4, Plausible or Umami), or gives a logo or an image as an address on another site. Search-console verification tags, if the owner adds them, are lines in the page that load nothing. Of its own, a site keeps three things in its reader's browser (the colour mode they chose, the language they chose, and which “also available in …” language banners they dismissed) and sends none of them anywhere; giscus comments and analytics, when its owner turns them on, keep their own data under their own terms.
